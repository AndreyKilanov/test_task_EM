# 🛡️ Система аутентификации, авторизации и управления доступом на основе ролей (RBAC)

Приложение реализует гибкую и безопасную систему аутентификации, регистрации и управления доступом к ресурсам с использованием модели **RBAC (Role-Based Access Control)**.

---

## 🌟 Основные возможности

### 🔐 Аутентификация и регистрация
- **Регистрация**:
  - Email
  - ФИО (фамилия, имя, отчество)
  - Выбор начальной роли: `creator` или `user`
- **Авторизация** через JWT-токен:
  - Логин по email и паролю
  - Возврат access и refresh токенов

### 🗑️ Управление аккаунтом
- **Мягкое удаление аккаунта**:
  - Устанавливает флаги `is_archived = True` и `is_active = False`
  - Данные сохраняются в БД для возможности восстановления аккаунта

### 🔑 Работа с паролями
- **Сброс пароля**:
  - Генерация 4-значного кода (временно возвращается в теле ответа — требуется подключение сервиса отправки email)
  - Код привязан к пользователю и имеет ограниченное время жизни
- **Изменение пароля** (для авторизованных пользователей)

### 👤 Профиль пользователя
Авторизованные пользователи могут:
- Редактировать email и ФИО
- Устанавливать или удалять аватар (в формате `base64`)
- Менять тему приложения (`light` / `dark`)

### 🔐 Управление доступом к ресурсам (Админка)
Администраторы могут управлять разрешениями через Django Admin:
- **Чтение** (`read`)
- **Запись** (`write`)
- **Удаление** (`delete`)
- **Полный доступ** (`manage`)

## 🗃️ Схема управления доступом (RBAC)

Реализована гибкая система на основе ролей с **динамическим управлением правами** через Django Admin.

### 🔒 Кастомный пермишен
Написан пермишен `DynamicRolePermission`, который:
- Проверяет наличие у роли пользователя разрешения на доступ к конкретному эндпоинту
- Учитывает HTTP-метод и сопоставляет его с соответствующим действием (`read`, `write`, `delete`)

### 🛠️ Управление через админ-панель
Администратор может:
1. В разделе **Role permission mappings**:
   - Назначать или удалять права для любой роли
2. В разделе **Permission**:
   - Создавать новые правила доступа
   - Удалять существующие разрешения

> 💡 _Все базовые права инициализируются автоматически при первом запуске приложения._

## 📦 Модели базы данных

### 1. `CustomUser`
Основная модель пользователя:

| Поле | Описание |
|------|----------|
| `email` | Уникальный email (используется для входа) |
| `first_name` | Имя |
| `middle_name` | Отчество |
| `last_name` | Фамилия |
| `avatar` | Фото профиля в формате `base64` |
| `role` | Роль пользователя (из enum `UserRole`) |
| `theme` | Предпочтительная тема интерфейса (`light`/`dark`) |
| `password_changed_at` | Дата последнего изменения пароля |
| `is_archived` | Флаг архивации аккаунта (мягкое удаление) |
| `archived_at` | Дата архивации |

### 2. `Permission`
Определяет разрешения на доступ к ресурсам:

| Поле | Описание |
|------|----------|
| `resource` | Путь API (например, `/api/v1/documents/`) |
| `action` | Действие: `read`, `write`, `delete` |

### 3. `RolePermission`
Связующая таблица между ролями и разрешениями:

| Поле | Описание |
|------|----------|
| `role` | Роль из enum `UserRole` |
| `permission` | Связь с моделью `Permission` (Foreign Key) |

### 🎭 Роли (`UserRole` enum)

- `admin` — полный доступ ко всем ресурсам
- `moderator` — расширенные права (например, создание документов)
- `creator` — ограниченные права на создание контента
- `user` — базовые права на чтение

## 🛡️ Защита ресурсов

Сопоставление HTTP-методов и действий:

| HTTP метод | Действие |
|------------|----------|
| `GET`      | `read`   |
| `POST`, `PUT`, `PATCH` | `write` |
| `DELETE`   | `delete` |

### 🔒 Примеры защищённых эндпоинтов

| Эндпоинт                | Метод  | Доступ                     |
|------------------------|--------|----------------------------|
| `/api/v1/documents/`   | `GET`  | Все авторизованные         |
| `/api/v1/documents/`   | `POST` | `moderator`, `admin`       |
| `/api/v1/reports/`     | `DELETE` | Только `admin`           |
| `/api/v1/users/`       | `GET`  | Только `admin`             |

---

## 📡 Ответы API

### ✅ Успешные ответы
- `200 OK` — для `GET` запросов
- `201 Created` — для успешного создания ресурса (`POST`)
- `204 No Content` — для успешного удаления (`DELETE`)

### ❌ Ошибки доступа
- `401 Unauthorized` — пользователь не авторизован
- `403 Forbidden` — авторизован, но не имеет необходимых прав

---

## 🧑‍💼 Администрирование

Все настройки прав доступны через стандартную **Django Admin** панель по адресу `/admin/`.

1. **Permissions** — управление правилами доступа к ресурсам  
2. **Role permission mappings** — привязка ролей к разрешениям

> 💡 _Система поддерживает горячее обновление прав без перезапуска сервера._
